# Coin Toss – Vanilla JavaScript

This project is more than just a small Coin Toss game for me. It represents one of the first JavaScript projects that I built step by step while making a serious effort to understand and write the code myself.

## Why I Built This

I wanted a simple project where I could practice JavaScript fundamentals without depending heavily on AI-generated solutions.

The goal was not just to make the game work. I wanted to understand:

* How functions work together
* How user input is handled
* How random computer choices are generated
* How conditions determine the result
* How scores are stored and updated
* How JavaScript changes what the user sees on the page
* How HTML, CSS, and JavaScript connect together

## How the Project Developed

I started with the basic game logic:

1. The user selects **Heads** or **Tails**.
2. JavaScript generates a random computer result.
3. The two choices are compared.
4. The game decides whether the user won or lost.

At first, most of the output was shown using `console.log()`.

As I continued improving the project, I gradually moved the results into the actual user interface.

## Features I Added

During development, I added:

* Heads and Tails selection
* Random coin toss generation using `Math.random()`
* Win and loss checking
* Score tracking
* Results displayed on the page
* Validation when the user tries to toss without selecting Heads or Tails
* Reset score functionality
* Improved button and game interaction
* Cleaner JavaScript structure as my understanding improved

## Learning Without Relying on AI

One of the most important parts of this project was changing how I learn programming.

In previous projects, I sometimes relied too much on AI to generate code. With this project, I tried to:

1. Understand the problem first.
2. Write the code myself.
3. Debug it myself.
4. Look at documentation or learning material.
5. Ask for guidance only when I was genuinely stuck.

Because of this, I can explain how this project works and why the code was written the way it was.

That makes this project personally more valuable to me than larger projects where I understood less of the implementation.
